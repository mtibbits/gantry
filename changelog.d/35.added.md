- `gantry refresh --config <file>`, the refresh job an OS scheduler runs
  every `interval_minutes`: under a lock in the new `[refresh] dir`, it runs
  the `[refresh] update` commands (no shell, a time limit, the process tree
  stopped on timeout), records the update in `update.json`, builds a new
  generation with `gantry build --output-dir` (which now writes a
  `build.json` completion marker) and swaps it in whole through `current`
  (docs/refresh-and-serve.md). The privacy promise now reads "Gantry itself
  opens no network connection": `gantry refresh` runs the update commands
  the installation config lists, which connect only where the operator
  points them.
