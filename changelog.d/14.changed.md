- A leaf's model tiers come from its `WBS.md` `thinking:` and `checking:`
  keys, read from devagent's portfolio JSON (schema 1.2 `models`). A
  project-level `step_models` class shows beside such a key on the same
  leaf, never alone. The estimates file becomes a per-leaf fallback for
  tiers: a leaf with none in the JSON takes its row's, and every leaf still
  takes its effort bucket, flags and hours from its row
  (docs/worksite-page.md#which-estimate-a-leaf-uses).
- devagent's `bad_model` entries (a malformed `thinking:` or `checking:`
  key) are shown on the panel as devagent wrote them, and a devagent
  warning about a leaf's model key is suppressed in their favour.
- Each lane's model table counts only haiku, sonnet, opus and fable;
  `inherit` and other values still show in the box's band as text, and a
  lane with none of the four draws no table.
- With a portfolio document older than schema 1.2, the
  `no_model_tiers` report line says the schema carries no tiers.
